ØLKARTET OSLO - DEPLOYMENT NOTES
=================================

WHAT THIS PROJECT IS
---------------------
A plain static site: index.html, app.js, style.css, and a pre-generated
data/bars.json. No server, no build step, no database. The only "backend"
is scripts/scrape.mjs, which you run locally/on-demand to refresh
data/bars.json and then commit + push the result.


DO YOU NEED SUPABASE? NO.
---------------------------
Nothing here needs a database:
- data/bars.json is static data, regenerated by a script, not written to
  by visitors. A flat JSON file of ~600 rows is trivial for a browser to
  fetch and filter - no query engine needed.
- The only "state" the app keeps (price filter, map position, the
  show/hide-nearby toggle) lives in each visitor's own browser via
  localStorage. It's per-device by design and doesn't need to sync
  anywhere, so there's nothing to centralize.
- There are no user accounts, no writes, no real-time features.

You'd only reach for Supabase (or any DB) if you later added something
that needs shared, server-side state - e.g. user accounts with synced
favorites across devices, visitor-submitted price corrections, comments/
ratings, or running the scraper server-side on a schedule and wanting
somewhere other than a git-committed JSON file to put the result. None
of that exists today, so keep it simple.


DEPLOYING TO CLOUDFLARE PAGES
-------------------------------
Repo is already on GitHub: https://github.com/prebenolsen/pilsguiden-location

1. Cloudflare dashboard -> Workers & Pages -> Create -> Pages ->
   Connect to Git -> pick this repo.
2. Build settings:
     Framework preset:     None
     Build command:        (leave empty)
     Build output directory: /
   There's nothing to build - Pages just needs to serve the repo as-is.
3. Deploy. Cloudflare gives you a *.pages.dev URL immediately; add a
   custom domain later under the project's "Custom domains" tab if you
   want one.
4. Every push to the connected branch (master) auto-deploys. That
   includes data updates - see below.

No environment variables or secrets are needed for the deploy itself.
(Nominatim calls only happen when you run the scraper locally, never
from the deployed site.)


KEEPING THE PRICE DATA FRESH
------------------------------
Manual (what you do today):
    npm run scrape            # upsert new/changed bars
    git add data/
    git commit -m "Refresh bar data"
    git push                  # Cloudflare Pages redeploys automatically

To automate it instead of remembering to run it:
  Add a scheduled GitHub Actions workflow (.github/workflows/scrape.yml)
  that runs on a cron, executes `node scripts/scrape.mjs`, and commits +
  pushes data/bars.json + data/geocode-cache.json if they changed. That
  push is what triggers the Cloudflare Pages redeploy - still no
  database involved, just CI doing the git commit for you. Ask me to set
  this workflow file up when you're ready for it.
